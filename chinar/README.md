# Чинар — сайт ресторана

Статический сайт ресторана, собранный под стандарты 2026 года: без фреймворков,
без внешних зависимостей, с проверками качества в CI.

Исходный сайт на Tilda (`https://chinar-restaurant.tilda.ws/`) переносится сюда
скриптом импорта — см. раздел **Перенос контента с Tilda**.

---

## Что внутри

| Возможность | Реализация |
|---|---|
| Рендеринг | Свой генератор статики на Node 22, шаблоны — теговые литералы с экранированием по умолчанию |
| Контент | Один источник правды: `content/site.ru.json` и `content/site.en.json` |
| Языки | RU (`/`) и EN (`/en/`), `hreflang`, переключатель в шапке |
| Стили | CSS без препроцессора: `@layer`, `oklch`, `light-dark()`, container queries, `:has()`, fluid-типографика на `clamp()` |
| Анимации | Scroll-driven (`animation-timeline: view()`), View Transitions; полностью отключаются при `prefers-reduced-motion` |
| Интерактив | ES-модули: тема, мобильное меню с ловушкой фокуса, фильтр и поиск по меню, форма брони, статус «открыто сейчас» |
| Доступность | WCAG 2.2 AA: скип-ссылка, ориентиры, видимый фокус, `aria-*` без висячих ссылок, цели нажатия ≥ 44 px |
| SEO | JSON-LD `Restaurant` + `Menu` + `WebSite`, канонические адреса, Open Graph с PNG-картинкой, `sitemap.xml`, `robots.txt` |
| PWA | `manifest.webmanifest`, service worker (network-first для страниц, cache-first для статики), офлайн-страница |
| Безопасность | CSP и заголовки в `_headers`, honeypot в форме, без сторонних скриптов |
| Тесты | 67 проверок: логика, парсер Tilda, собранный HTML (ссылки, a11y, разметка, бюджет веса) |

Внешних зависимостей нет вообще: `node_modules` не нужен, `npm install` не требуется.

## Быстрый старт

```bash
cd chinar
npm run dev        # сборка + сервер на http://127.0.0.1:4173 с live-reload
npm run verify     # проверка контента + все тесты
npm run build      # продакшен-сборка в dist/
```

Полезные команды:

```bash
npm run check          # что в контенте осталось заглушкой
npm run check:strict   # то же, но с ненулевым кодом выхода (для релиза)
npm run assets         # перегенерировать логотип, иконки, OG-картинку
npm run clean          # удалить dist/
SITE_URL=https://chinar.ru npm run build            # канонические URL и sitemap под ваш домен
BASE_PATH=/chinar npm run build                     # если сайт лежит в подкаталоге
```

## Перенос контента с Tilda

Скрипт читает живую страницу Tilda и вытаскивает из неё заголовки, тексты,
меню с ценами, телефоны, почту, адрес, часы работы, соцсети и ссылки на фото.

```bash
# 1. Посмотреть, что скрипт нашёл (ничего не перезаписывается)
npm run import -- https://chinar-restaurant.tilda.ws/

# 2. Применить к content/site.ru.json (создаётся резервная копия .bak)
npm run import -- https://chinar-restaurant.tilda.ws/ --merge

# Если страница рисует меню через JavaScript — сохраните её из браузера
# («Сохранить как» → полная страница) и укажите файл:
npm run import -- --from-file ~/Downloads/chinar.html --merge
```

После импорта:

1. Проверьте diff `content/site.ru.json`.
2. Скачайте фотографии по ссылкам из отчёта в `src/assets/img/` и пропишите их в
   `gallery.items`, `hero`, `about`. Заглушки — это сгенерированные SVG, их нужно заменить.
3. Переведите изменения в `content/site.en.json` (структура должна совпадать —
   `npm run check` предупредит о расхождении).
4. Заполните `contacts.geo`, `contacts.mapEmbedUrl`, `seo.siteUrl`, `reservation.endpoint`.
5. Поставьте `meta.dataStatus: "verified"` — баннер «демо-данные» исчезнет.
6. `npm run verify && npm run build`.

## Контент

Весь текст, цены и контакты живут в `content/site.<locale>.json`. HTML править не нужно.

Ключевые поля:

- `meta.dataStatus` — пока не `verified`, на всех страницах показывается баннер о демо-данных.
- `contacts.phoneHref` — только цифры и `+`, используется в `tel:` и в JSON-LD.
- `hours` — расписание в кодах дней (`Mo`…`Su`). Закрытие раньше открытия означает работу за полночь;
  статус «открыто сейчас» это учитывает.
- `menu.categories[].items[].price` — число или `null`. `null` выводится как «—» и не попадает в JSON-LD.
- `reservation.endpoint` — пустое значение = демо-режим (заявка только в консоли).
  Любой https-URL (Formspree, Getform, своя функция) начнёт получать JSON вида
  `{name, phone, date, time, guests, comment, submittedAt, page}`.

`npm run check` перечисляет всё, что осталось незаполненным, и ошибки структуры:
неизвестные коды дней, дубли дней, отрицательные цены, битые `id` разделов,
слишком длинные title/description, расхождения между языками.

## Деплой

`dist/` — обычная статика, подходит любой хостинг.

- **GitHub Pages** — workflow `.github/workflows/chinar-site.yml` собирает и публикует
  с ветки `main`. Задайте переменную репозитория `SITE_URL`, иначе канонические
  адреса останутся на `example.com`. Для project-страницы (`.../<repo>/`) workflow
  сам подставит `BASE_PATH=/<repo>`; для своего домена задайте `BASE_PATH` пустой строкой.
- **Netlify / Cloudflare Pages** — build: `npm run build`, publish: `chinar/dist`.
  Файл `_headers` с CSP и кэшированием подхватится автоматически.
- **Свой nginx** — раздавайте `dist/`, перенесите правила из `_headers` в конфиг.
  `sw.js` отдавайте с `Cache-Control: no-cache`.

`BASE_PATH` влияет только на абсолютные пути: `scope` и `start_url` манифеста,
список precache и офлайн-страницу в service worker. Ссылки между страницами и на
ассеты относительные, поэтому работают при любом размещении.

Service worker регистрируется только по HTTPS, поэтому на `http://localhost` он не мешает разработке.

## Проверки качества

`npm test` гоняет 67 проверок, среди них:

- все относительные `href`/`src` существуют в `dist`;
- каждый якорь `#id` имеет цель, каждый `aria-labelledby` — существующий элемент;
- ровно один `<h1>` на страницу, у всех `<img>` есть `alt`, `width`, `height`;
- JSON-LD разбирается, содержит `Restaurant` с меню, и **не** содержит выдуманных координат;
- приватные страницы не попали в `sitemap.xml`;
- все файлы из precache service worker реально существуют;
- бюджет веса: HTML < 120 kB, CSS < 60 kB, JS < 40 kB.

## Ограничения текущей версии

- Контакты, цены, отзывы и фотографии — **демо-данные**. Исходный сайт Tilda не был
  доступен из среды сборки, поэтому реальные значения не подставлены. Порядок замены —
  раздел «Перенос контента с Tilda».
- Изображения — сгенерированные SVG-заглушки. Под реальные фото уже готова разметка
  с `width`/`height`, `loading="lazy"` и `decoding="async"`.
- Онлайн-оплаты и корзины нет: форма брони отправляет заявку, оплата происходит в зале.
