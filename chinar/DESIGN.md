# Chinar — дизайн-система и спецификация

Документ описывает UI-кит, параметры компонентов (для сборки в Figma) и карту
переноса реализации на продакшен-стек `Next.js + Tailwind + GSAP + Lenis + CMS`.

---

## 1. Дизайн-токены

Источник истины — `assets/css/tokens.css`. Ни одно значение ниже не должно
дублироваться в компонентах.

### Цвет

| Токен | Значение | Роль |
|---|---|---|
| `--c-obsidian` | `#0A0A0A` | основной фон (графитовый, не плоский чёрный) |
| `--c-obsidian-2` | `#121212` | поверхность второго уровня |
| `--c-gold` | `#D4AF37` | акцент по умолчанию |
| `--c-terracotta` | `#A94028` | альтернативный акцент |
| `--c-ivory` | `#F5F5F0` | основной текст |

Акцент переключается целиком, без правок компонентов:
`<html data-accent="terracotta">`. Все свечения и активные состояния
считаются от `--accent-rgb`, поэтому меняются вместе с темой.

Текстовые ступени прозрачности: `70%` — вводные абзацы, `45%` — капшены и
подписи, `12%` — разделители и бордеры.

### Типографика

| Роль | Шрифт | Размер |
|---|---|---|
| Hero | Playfair Display, 400 | `clamp(3rem, 10vw, 9rem)` |
| H2 | Playfair Display, 400 | `clamp(2rem, 5.2vw, 4.25rem)` |
| H3 / название блюда | Playfair Display, 400 | `clamp(1.35rem, 2.2vw, 2rem)` |
| Lead | Montserrat, 300 | `clamp(1rem, 1.35vw, 1.2rem)` |
| Body | Montserrat, 300 | `clamp(0.94rem, 1.05vw, 1.02rem)` |
| Caption | Montserrat, 400, `letter-spacing: 0.22em`, uppercase | `0.78rem` |

Межстрочное: `1.04` у антиквы, `1.65` у наборного текста. Трекинг заголовков
`-0.015em`, у hero `-0.03em`. Подключение шрифтов неблокирующее, при недоступности
CDN включается системный фолбэк (`serif` / `Helvetica`) — метрики близки,
верстка не «прыгает».

### Glassmorphism (параметры для Figma)

| Параметр | Значение |
|---|---|
| Background blur | `24px` (+`saturate(140%)`) |
| Заливка | белый `6%` (диапазон брифа 5–10%) |
| Внутренний бордер | `0.5px`, белый `10%` |
| Радиус | `18px` (карточки — `20px`) |

Фолбэк для браузеров без `backdrop-filter`: непрозрачная заливка
`rgba(10,10,10,0.55)` — иначе панель становится нечитаемой.

### Свечение

Активные и интерактивные элементы: `Drop Shadow`, цвет акцента,
`Blur 15–20px`, `Spread 0`, прозрачность `28%` в покое и `45%` в ховере.
Резких контуров нет — только мягкое отделение от фона.

### Сетка и ритм

* Контент-максимум `1440px`, боковые поля `clamp(1rem, 4vw, 4.5rem)`.
* Вертикальный ритм секции `clamp(5rem, 12vh, 10rem)`.
* Bento-сетка: 4 колонки (десктоп) → 2 (≤1024px) → 1 (≤720px);
  модули `lg (2×2)`, `wide (2×1)`, `tall (1×2)`, `sm (1×1)`.

### Движение

| Токен | Значение | Применение |
|---|---|---|
| `--ease-out-expo` | `cubic-bezier(0.16, 1, 0.3, 1)` | появления, ховеры |
| `--ease-inout` | `cubic-bezier(0.65, 0, 0.35, 1)` | циклические анимации |
| `--dur-fast` | `0.25s` | состояния элементов |
| `--dur-base` | `0.6s` | смена состояний блока |
| `--dur-slow` | `1.1s` | reveal on scroll |

## 2. Архитектура интерфейса

| Блок | Решение | Реализация |
|---|---|---|
| Header | Плавающая glass-панель, лого по центру, «Бронь стола» слева, бургер справа. Скрывается при скролле вниз, возвращается при скролле вверх | `.header`, `app.js` |
| Меню | Полноэкранный оверлей, каскадное появление строк, закрытие по `Esc` | `.navmenu` |
| Hero | `100svh`, зацикленное макро-видео (9:16 на мобильном) + скрим, каллиграфический заголовок с маскирующим появлением, пульсирующий якорь | `.hero` |
| Концепция | Асимметричная сетка: два кадра и стеклянный текстовый блок в одной grid-строке с намеренным перекрытием; параллакс `+0.12 / −0.08` | `.concept` |
| Меню блюд | Bento-сетка, фильтр по категориям, ховер: `scale 1.05` внутри маски, уход градиентного затемнения, раскрытие описания | `.bento`, `.dish` |
| Интерьер | Вертикальный скролл → горизонтальная прокрутка; высота секции = ширине трека; прогресс-бар. На ≤720px — нативный свайп со snap | `.interior`, `initHorizontal` |
| Бронирование | Форма на странице, кастомный календарь и слоты в стекле, счётчик гостей, валидация, отправка на endpoint | `.booking`, `booking.js` |

## 3. Motion-слой: соответствие библиотекам

Реализовано на vanilla JS (в среде сборки недоступен npm), но один в один
ложится на связку GSAP + Lenis — поведение и тайминги сохраняются.

| Эффект | Текущая реализация | Продакшен |
|---|---|---|
| Инерционный скролл | `createSmoothScroll()` — липованная позиция поверх нативного скролла, `lerp 0.095` | `new Lenis({ lerp: 0.095 })` + `gsap.ticker` |
| Reveal on scroll | `IntersectionObserver` + классы `.reveal` / `.mask-line` | `ScrollTrigger.batch()` + `gsap.from(y: 32, autoAlpha: 0)` |
| Магнитные кнопки | `initMagnetic()` — притяжение в радиусе 90px, сила `0.32`, лейбл двигается на `0.35` от смещения | `gsap.quickTo(el, "x")` |
| Параллакс | `initParallax()` — прогресс блока в вьюпорте → `translateY` | `ScrollTrigger` + `scrub: true` |
| Горизонтальная секция | `initHorizontal()` — sticky-пин и перевод вертикального прогресса в `translateX` | `ScrollTrigger` + `pin: true`, `scrub` |
| Курсор-компаньон | `initCursor()` — липованное кольцо, `mix-blend-mode: difference` | без изменений |

Во всех модулях первым условием проверяется `prefers-reduced-motion`.

## 4. Перенос на Next.js

Разделение «данные → разметка → движение» уже сделано, поэтому миграция
механическая:

1. `content.js` → схемы CMS. Объекты `brand`, `hero`, `concept`, `menu`,
   `interior`, `booking` становятся документами Sanity/Strapi один в один;
   `menu.dishes[].size` — поле-селект (`lg | wide | tall | sm`), которым
   владелец управляет акцентами bento-сетки без правки вёрстки.
2. `render.js` → серверные React-компоненты (`<Hero>`, `<Concept>`, `<BentoMenu>`,
   `<InteriorScroller>`, `<BookingForm>`). Функции уже принимают ровно те данные,
   которые получат пропсами.
3. `motion.js` / `booking.js` → клиентские компоненты (`"use client"`),
   эффекты заменяются вызовами GSAP/Lenis по таблице выше.
4. `tokens.css` → `tailwind.config.ts` (`theme.extend.colors`, `fontFamily`,
   `boxShadow.glow`, `backdropBlur.glass`). Значения переносятся без изменений.
5. Форма брони → `app/api/booking/route.ts`: валидация на сервере,
   rate-limit по IP, запись в CRM/почту. Ключи интеграций — только в
   серверных переменных окружения, на клиент не попадают.

### Что проверить перед релизом

* Вес hero-видео и `poster`-кадр (LCP), реальные фото в AVIF/WebP + `sizes`.
* Schema.org `Restaurant` с реальными адресом, телефоном и часами.
* Политика обработки персональных данных и чекбокс согласия в форме брони —
  форма собирает имя и телефон.
